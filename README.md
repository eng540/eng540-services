## قواعد التحقق المنهجية
- ✅ **متحقق** — مصدر رسمي سعودي بتاريخه (بلدي، ناجز، SLA وزارة العدل، geosa.gov.sa…)
- 📚 **معرفة مهنية** · 💼 **ممارسة تجارية** · 🧪 **مثال توضيحي**
- ⚠️ **يحتاج تحقق** — يوسم صراحة ويُسجل في [سجل الفجوات](https://eng540.github.io/eng540-services/pages/10-QUALITY-AND-UPDATES/Knowledge-Gaps.html)
- **بيانات المنصة التفاعلية إرشادية**: المصدر المركزي `app-data.js` موثق بتاريخ تحقق؛ الرسوم والمدد النهائية تعتمدها الجهة المختصة لكل حالة — لا فاتورة رسمية من الحاسبة ولا قرار نظامي من المشخّص

## البنية والمصدر الواحد للحقيقة
```
├── index.html + assets/ + pages/   ← الموقع الثابت (GitHub Pages · sitemap · robots · 404)
├── app.html + app-data.js          ← المنصة التفاعلية · بياناتها المركزية (المصدر الوحيد للواجهة)
├── source/                          ← ملفات Markdown (المصدر الوحيد للموسوعة)
└── tools/
    ├── build_site.py               ← المولّد v3: بادئة مسار لكل عمق + فهارس أقسام + SEO + og/canonical
    ├── linkcheck.py                ← فاحص روابط شامل (149 ملفاً · 26,431 مرجعاً — صفر أخطاء)
    ├── separate_app_data.py        ← فصل بيانات الواجهة إلى app-data.js
    └── style.css / app.js          ← طبقة العرض والتفاعل (تبويبات، متتبع 25 خطوة، بحث، وضع ليلي)
```

## إعادة البناء بعد تعديل المحتوى
```bash
python3 tools/build_site.py    # يقرأ source/ ويولّد pages/ + الفهارس + فهرس البحث + sitemap
python3 tools/linkcheck.py     # فحص شامل للروابط قبل النشر
```
ثم `git add -A && git commit && git push` — وGitHub Pages يبني تلقائياً (قد يتأخر الطابور دقائق).
